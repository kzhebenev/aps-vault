# APS Vault — ревизия безопасности по коду (02.10.2026)

Объект: `/aps/vault` на коммите `vault/mcp: MCP-сервер…` (21.06.2026), версия в коде 0.3.2
(в git — v0.3.3). Метод: чтение всего бэкенда (`crypto.py`, `db.py`, `main.py`, `sdk_api.py`,
`oidc.py`, `state.py`), фронтенда (`app.js`, `index.html`, `nginx.conf`), `mcp/server.py`,
`ops/*`, Dockerfile'ов и compose. Живых атак на vault.devkz.ru не проводилось — это ревизия
кода, не пентест площадки. В проде сейчас 362 секрета, 42 папки, 29 активных service-токенов,
119 тыс. записей аудита.

## Итог одной строкой

Криптографическое ядро сделано правильно и без самодеятельности (Argon2id → AES-256-GCM,
envelope-ключи на папку, токены хранятся хешами, значения в БД нечитаемы без мастера или
токена). Слабые места — не в криптографии, а по краям: доверие к `X-Forwarded-For`,
слишком широкий CORS, захардкоженный домен, отсутствие тестов и мёртвый код. Всё это
правится за день. **Выкладывать не стыдно — после пунктов «До публикации».**

## Что сделано хорошо

- **KDF и шифр.** Argon2id (m=64 МиБ, t=3, p=4) из мастер-пароля; AES-256-GCM, 96-битный
  случайный nonce на каждую запись, тег 128 бит; проверка пароля через зашифрованный
  маркер, а не хеш пароля (`crypto.py`).
- **Envelope-архитектура.** У каждой папки свой случайный ключ, зашифрованный мастер-ключом;
  service-токен несёт свою копию ключа папки под KDF(токен). Поэтому machine API работает
  при заблокированном vault, а компрометация токена даёт ровно одну папку (`db.py:131`,
  `sdk_api.py:67`).
- **Токены и ссылки — только хеши.** В БД лежит SHA-256 от токена; сырой показывается один
  раз. Share-ссылки — то же, с TTL и лимитом открытий.
- **Recovery без потери данных.** Код восстановления расшифровывает копию мастер-ключа и
  перешифровывает ключи папок под новый пароль; старые сессии сбрасываются (`main.py:540`).
- **Сессии.** HttpOnly + Secure + SameSite=Lax, 8 часов; CSRF double-submit с timing-safe
  сравнением; security-заголовки (HSTS, nosniff, frame-ancestors none).
- **OIDC сделан аккуратно.** PKCE S256, state и nonce в HttpOnly-cookie, RS256 через JWKS с
  повтором при неизвестном kid, строгая проверка iss/aud/exp/nonce, `email_verified`,
  белый список доменов, в логи не попадают токены (`oidc.py`).
- **Фронтенд без innerHTML.** Весь DOM строится через `el()` с `textContent`; единственный
  `innerHTML = ''` — очистка. Автоблокировка UI через 15 минут бездействия.
- **Журнал аудита** на каждое чтение/запись/вход, включая machine API и share-ссылки.
- **Защита от инъекции команд** в CLI уже чинилась (`shlex.quote`, коммит 10.06).

## Находки

Оценка — по влиянию на конфиденциальность секретов при реалистичном сценарии.

### HIGH

**H1. Лимит попыток входа обходится заголовком `X-Forwarded-For`.**
`main.py:189` берёт *первый* элемент `X-Forwarded-For`. За прокси (NPM/nginx) заголовок
дописывается справа, а левую часть присылает клиент — значит, атакующий подставляет любой
IP и получает бесконечные попытки `/api/auth/unlock` и `/api/auth/recover` (ограничение —
только ~0,5 с Argon2 на попытку). Тот же код в `sdk_api.py:51`. Таблица `Lockdown` в
`db.py:173` объявлена, но не используется.
*Фикс:* брать IP из `X-Real-IP`/последнего элемента XFF и только от доверенного прокси
(`TRUSTED_PROXIES`), иначе `request.client.host`; лимит — ещё и глобальный (на все IP), и
персистентный (таблица `lockdown`), чтобы переживал рестарт.

**H2. CORS с credentials для любого расширения браузера и любого localhost.**
`main.py:68`: `chrome-extension://[a-z]+$`, `moz-extension://…`, `http://localhost(:\d+)?`
разрешены с `allow_credentials=True`. Любое установленное у администратора расширение
(или локальный процесс на любом порту, открывший страницу) может читать API с его cookie.
*Фикс:* список origin'ов из env (`VAULT_ALLOWED_ORIGINS`), для расширения — конкретный
ID; localhost — только при `VAULT_DEV=1`.

### MEDIUM

**M1. `/api/init` открыт без защиты.** Свежий инстанс, выставленный наружу до инициализации,
инициализирует первый пришедший (`main.py:306`). *Фикс:* одноразовый `VAULT_INIT_TOKEN` из
env либо принимать `/api/init` только с loopback.

**M2. URL секрета отрисовывается как `<a href>` без проверки схемы** (`app.js:589`).
Токен с `can_write` (или импорт JSON) может записать `javascript:`-URL; клик администратора
в UI — выполнение кода в origin'е vault. `rel=noopener` смягчает, но не гарантирует.
*Фикс:* сервер принимает `url` только `http(s)://` (Pydantic-валидатор) + фронт не делает
ссылку из других схем.

**M3. Rate-limit и сессии только в памяти процесса.** Один uvicorn-воркер — иначе сессии и
лимиты разъедутся; при рестарте счётчики обнуляются. Задокументировать «один воркер» и
перенести лимит в БД (см. H1).

**M4. Webhooks объявлены, но никогда не срабатывают.** `_fire_webhook` не вызывается ни из
одного обработчика (`main.py:1247`). Для пользователя — функция, которая «настроилась, но
молчит». Либо подключить к событиям, либо убрать из API/UI. Если подключать — проверить
URL на внутренние адреса (SSRF: webhook может бить в 169.254.169.254 / внутренние
сервисы), сейчас проверяется только схема.

**M5. Discovery и JWKS OIDC допускают `http://`** (`oidc.py:87`). При ошибочном `OIDC_ISSUER`
по http ключи подписи приедут без TLS. *Фикс:* только https, кроме `VAULT_DEV=1`.

### LOW

**L1. Лишняя и уязвимая зависимость.** `python-jose==3.3.0` (CVE-2024-33663/33664) в
`requirements.txt`, но нигде не импортируется; `slowapi` тоже не используется. Убрать.
**L2. Tailwind с CDN** (`index.html:8`) — внешняя зависимость во время выполнения у секрет-
менеджера: не работает в закрытом контуре и расширяет цепочку поставки; CSP из-за этого
содержит `'unsafe-inline'` и CDN. Собрать CSS в репозиторий.
**L3. Молчаливые `except: pass`** при записи истории (`main.py:780`) и в экспортных
расшифровках — ошибка целостности пройдёт незамеченной. Логировать.
**L4. Share-ссылка: `used_count` увеличивается не атомарно** — параллельные открытия могут
превысить `max_uses` на единицу.
**L5. Версии расходятся:** `VERSION`=0.3.2, `main.py`=0.3.2, git-тег v0.3.3, `mcp/pyproject`
=0.1.0. Одна точка правды.
**L6. Контейнер работает от root**, порт 8086 опубликован на `0.0.0.0` в compose (на devkz
закрыт ufw, у стороннего пользователя — не факт). Добавить `USER`, публиковать на
`127.0.0.1`.
**L7. Нет автотестов.** Для криптографии и auth-потоков это главный долг перед публикацией.

### Не является уязвимостью, но надо честно описать в документации

- Один мастер-пароль на инстанс: нет пользователей, ролей и разделения прав в UI (есть
  только scope-токены). Это однопользовательский/командный vault, не замена Vault/Infisical
  для сотен сотрудников.
- Любой, у кого есть валидная сессия, видит все папки (мастер-ключ один).
- `VAULT_MASTER_PASSWORD` в env для авто-разблокировки при OIDC — осознанный dev-компромисс
  (`oidc.py:7`), в проде недопустим; документация должна об этом кричать.
- Экспорт отдаёт все секреты открытым текстом — по замыслу, под мастер-сессией, с записью
  в аудит.
- Zeroize мастер-ключа в Python невозможен — комментарий в `state.py:23` это признаёт.

## До публикации (обязательно)

1. Исправить H1, H2, M1, M2, M5, L1 — суммарно ~150 строк.
2. Убрать привязку к devkz: CORS, `OIDC_*` в compose, метка TOTP `vault.devkz.ru`
   (`main.py:483`), URL по умолчанию в `mcp/server.py` и `ops/vault-cli.sh` → всё в env;
   `.env.example`.
3. Решить судьбу webhooks (M4): подключить или вырезать.
4. Добавить тесты: криптопримитивы (round-trip, tamper → InvalidTag), init/unlock/lock,
   неверный пароль × N → 429, service-token scope (чужая папка → 404), can_write=false →
   403, share-ссылка (TTL, лимит), CSRF (без заголовка → 403). Запуск в CI.
5. Привести версию к одной (0.4.0 для публичного релиза), CHANGELOG.
6. Перевести сообщения API на английский или оставить русскими, но сказать об этом в README
   (сейчас `detail` — по-русски).
7. Проверить историю git: секретов нет (проверено — только плейсхолдер `vlt_xxx…`), но есть
   упоминания хостов исходной инсталляции в комментариях —
   вычистить или смириться (не секрет, но чужому читателю мешает).
