# APS Vault

Небольшой self-hosted менеджер секретов для одной команды: веб-интерфейс для людей,
machine API со scope-токенами на папку для сервисов и ИИ-агентов, и ничего, что ходит
наружу.

## Зачем ещё один vault

HashiCorp Vault и ему подобные рассчитаны на сотни инженеров и команду, которая их
обслуживает. APS Vault — для обратного случая: несколько человек, десятки сервисов и агентов,
один сервер. Это несколько тысяч строк Python и чистого JavaScript, одна SQLite-база (или одна
PostgreSQL, когда нужны реплики), и всё читается за вечер.

- **Шифрование, которое остаётся шифрованием.** Argon2id выводит мастер-ключ из мастер-пароля;
  у каждой папки свой случайный ключ, завёрнутый мастер-ключом; каждое значение — AES-256-GCM
  со своим nonce. База без мастер-пароля или токена бесполезна.
- **Service-токены на папку.** Токен открывает ровно одну папку и работает даже при
  заблокированном vault — он несёт свою зашифрованную копию ключа папки. По умолчанию только
  чтение; `notes`, `totp` и `write` включаются отдельно на каждый токен.
- **Machine API прежде всего.** `GET /api/v1/m/secret/<имя>` с Bearer-токеном — всё, что нужно
  сервису. Есть CLI, клиенты на Python, Node, Go и Java, MCP-сервер для агентов и расширение
  браузера.
- **Готовность к постквантовой эре.** Запечатанный конверт может быть **гибридом X25519 + ML-KEM-768**
  (FIPS 203) или, для ГОСТ-инсталляций, **гибридом ГОСТ Р 34.10-2012 + ML-KEM-768** с Кузнечиком-MGM на
  проводе: классическое и решётчатое согласование ключей вместе дают один ключ, и записанный сегодня
  трафик останется закрытым для квантового компьютера завтра. Все четыре клиента открывают оба.
- **Запечатанная доставка.** Токен привязывается к публичному ключу X25519 приложения, и
  значения уходят из хранилища зашифрованными на него: по пути их не читает никто, а украденный
  токен без ключа бесполезен. Клиенты расшифровывают у себя. См. [docs/SEALED.md](docs/SEALED.md).
- **Регистрация узлов.** Выдай одноразовый код; узел сам сделает пару ключей и получит
  запечатанный токен одной командой — токены никто не копирует руками. Пара ключей может жить
  внутри TPM или любого PKCS#11-токена (P-256) и никогда не покидать устройство.
  См. [docs/ENROLLMENT.md](docs/ENROLLMENT.md).
- **Аппаратный токен для мастер-ключа.** Мастер-ключ заворачивается ключом внутри PKCS#11-токена
  (HSM или SoftHSM2; механизмы ГОСТ для КриптоПро / Рутокен настраиваются), вход — PIN-кодом;
  ключ обёртки токен не покидает. См. [docs/HSM.md](docs/HSM.md).
- **Алгоритмы ГОСТ, если нужны.** `VAULT_CIPHER=gost` переводит всё хранилище на
  Кузнечик-MGM, Стрибог и KDF_TREE (ГОСТ Р 34.12/34.11-2012, RFC 9058), а ключ клиента по
  ГОСТ Р 34.10 даёт запечатанную доставку через VKO + Кузнечик-MGM во всех четырёх клиентах —
  с проверкой по тестовым векторам стандартов; соответствие по алгоритму, не сертифицированное
  СКЗИ. См. [docs/GOST.md](docs/GOST.md).
- **Зашифрованные резервные копии в S3.** При каждом изменении (или раз в час) плюс полная копия в сутки, на ключ,
  которого нет на сервере (по умолчанию постквантовый гибрид), вместе с настройками окружения; восстанавливается в SQLite и PostgreSQL. См.
  [docs/BACKUP.md](docs/BACKUP.md).
- **Облачный KMS для мастер-ключа.** AWS KMS или Yandex Cloud KMS как ключ обёртки; с PIN мастер-ключ
  дополнительно заворачивается локально под Argon2id(PIN): одних облачных ключей мало, а PIN не попадает
  в журналы провайдера; без PIN ячейка обслуживает SSO всего кластера.
  См. [docs/KMS.md](docs/KMS.md).
- **Ключи безопасности и биометрия.** YubiKey, Touch ID, Windows Hello, Android через WebAuthn.
  С расширением PRF мастер-ключ заворачивается секретом аутентификатора и вход — одно касание;
  без него ключ работает как второй фактор.
- **TOTP у пользователей, менеджеры выдают права, ключ папки можно сменить.** Одноразовые коды к
  паролю пользователя; менеджер папки выдаёт роли на свои папки без администратора; администратор
  перешифровывает папку после отзыва доступа (токены папки отзываются по именам). См.
  [docs/USERS.md](docs/USERS.md).
- **Люди с ролями.** Пригласи пользователей по e-mail; у каждого роль на папку — читатель,
  редактор или менеджер — и ничего лишнего на экране. Ключи папок приходят им запечатанными на
  их собственную пару ключей, так что в базе по-прежнему нет открытых ключей, а владелец не
  знает их паролей. Журнал подписывает действия именем. См. [docs/USERS.md](docs/USERS.md).
- **Подтверждение чтения.** Помеченный секрет человек читает только после того, как второй
  человек подтвердит по ссылке — без учётной записи, своим паролем подтверждающего; уведомление
  уходит на любой вебхук. См. [docs/APPROVALS.md](docs/APPROVALS.md).
- **Секреты только для машин.** Флаг — и ни один человек не увидит значение: ни в карточке, ни
  в истории, ни в экспорте, ни по ссылке; сервер сам генерирует и ротирует его, читают только токены.
- **Ротация в целевой системе.** Хранилище меняет пароль *в PostgreSQL* или *MySQL/MariaDB*
  (`ALTER ROLE` / `ALTER USER`), *в LDAP-каталоге* (`userPassword` / `unicodePwd` через учётку bind),
  *на хосте по SSH* (`chpasswd` с закреплённым ключом хоста) или через подписанный вызов твоего
  HTTP-приёмника — по кнопке или по расписанию — всегда с входом новым паролем как доказательством
  и откатом при отказе, и сохраняет новую версию только после того, как система её приняла.
  См. [docs/ROTATION.md](docs/ROTATION.md).
- **Переезжай со своими секретами.** Импорт из Bitwarden / Vaultwarden, KeePass (XML или сама база `.kdbx`),
  1Password, LastPass, Dashlane, Keeper, Passbolt, Passwork (файлы или его API), CSV, `.env` или прямо из
  HashiCorp Vault / Stronghold — с предпросмотром до записи. См. [docs/IMPORT.md](docs/IMPORT.md).
- **Kubernetes, Ansible, Terraform.** External Secrets Operator синхронизирует секреты в Kubernetes Secrets
  штатным провайдером `vault` (мы говорим на диалекте HashiCorp KV v2) — без своего контроллера;
  Ansible читает секреты lookup-плагином `aps_vault`; Terraform / OpenTofu читают и ведут секреты
  провайдером `apsvault`. См. [docs/KUBERNETES.md](docs/KUBERNETES.md),
  [clients/ansible](clients/ansible/README.md) и [docs/TERRAFORM.md](docs/TERRAFORM.md).
- **Пайплайны.** GitHub Action и шаблон GitLab CI превращают секреты в замаскированные переменные
  окружения для следующих шагов — токеном только на чтение и только на одну папку. См. [docs/CI.md](docs/CI.md).
- **Версии для ротации ключей.** Каждая смена значения — нумерованная версия; machine API и
  HashiCorp-фасад читают `?version=N`, так что сервис расшифровывает старые файлы старым ключом,
  пока новые уже шифруются новым.
- **TOTP внутри.** Рядом с паролем хранится 2FA-seed, API отдаёт текущий код.
- **Аудит всего.** Каждая разблокировка, чтение, запись, обращение токена и открытие ссылки —
  с IP и user-agent; выгрузка в syslog/SIEM (JSON или CEF), метрики Prometheus, журнал для fail2ban.
- **Восстановление.** Одноразовый recovery-код перезаворачивает мастер-ключ без перешифровки
  данных. Второй фактор TOTP на мастер-пароль и вход через OIDC — по желанию; владельцем через OIDC входят
  только учётки из `VAULT_OIDC_OWNERS`.
- **Интерфейс для ежедневной работы.** Список + карточка с прямыми ссылками, палитра ⌘K и
  клавиатура, тёмная/светлая тема, генератор паролей (случайный или парольная фраза) с честной
  оценкой энтропии, проверка утечек через Have I Been Pwned без передачи пароля (k-анонимность),
  отчёт о здоровье (слабые, повторяющиеся, просроченные, забытые), сроки ротации, живой TOTP,
  перетаскивание реквизитов, одноразовые ссылки на секрет и на заметку, история значений,
  экспорт/импорт JSON. Работает на телефоне. [docs/COMPARISON.md](docs/COMPARISON.md) —
  рядом с Bitwarden, 1Password, Passbolt, HashiCorp и Infisical.
- **Сторож токенов.** Каждый токен запоминает, откуда и как им пользуются; новая сеть, два места
  одновременно, всплеск частоты или перебор секретов — сигнал (журнал, вебхук, уведомитель) или
  заморозка токена; канареечные токены срабатывают на любое использование; сканер находит утёкшие
  токены в репозиториях по хешу. См. [docs/TOKEN-WATCH.md](docs/TOKEN-WATCH.md).
- **Политики «откуда и когда».** Токен (или весь интерфейс) ограничивается сетями-источниками,
  окнами времени и клиентским сертификатом (mTLS); украденный токен не с того адреса получает
  отказ и попадает в журнал.
- **Кластер.** Несколько реплик за балансировщиком на одной PostgreSQL ведут себя как один
  vault: сессии, счётчики брутфорса и верификатор — в базе, мастер-ключ едет внутри сессии,
  завёрнутый ключом, который есть только в cookie. См. [docs/CLUSTER.md](docs/CLUSTER.md).
- **API, совместимый с HashiCorp Vault / Deckhouse Stronghold** (`/v1/<папка>/data/<имя>`,
  `LIST`, `lookup-self`, `X-Vault-Token`): `hvac` и `vault` CLI работают без изменений —
  см. [docs/COMPATIBILITY.md](docs/COMPATIBILITY.md).
- **Интерфейс на русском и английском.**

## Быстрый старт

Из готовых образов, с **обновлением по кнопке** в Настройки → Обновление (агент проверяет выпуск и подписи Sigstore,
делает резервную копию, обновляет и при сбое возвращает прежнюю версию — [docs/UPDATES.md](docs/UPDATES.md)):

```bash
git clone https://github.com/kzhebenev/aps-vault.git && cd aps-vault
deploy/images/install.sh /opt/aps-vault                      # покажет адрес и init-token
```

Или сборка из исходников:

```bash
git clone https://github.com/kzhebenev/aps-vault.git && cd aps-vault
cp .env.example .env            # заполнить: публичный URL, разрешённые origin'ы, init-token
mkdir -p data && chown 10001:10001 data
docker compose up -d --build
open http://127.0.0.1:8087      # ввести init-token, задать мастер-пароль (≥12 символов), сохранить recovery-код
```

Дальше: папка → секрет → service-токен на эту папку → чтение из сервиса:

```bash
curl -s -H "Authorization: Bearer vlt_…" https://vault.example.com/api/v1/m/secret/db-password
```

Бэкенд ставится за reverse-proxy с TLS: cookie помечены `Secure`, по голому HTTP из браузера
работать не будет. Подробности — в [Развёртывании](docs/DEPLOYMENT.md).

## Клиенты

| Клиент | Где | Примечания |
|---|---|---|
| Python | `pip install aps-vault` (PyPI) или `clients/python/` | только стандартная библиотека, 3.9+ (`cryptography` — для запечатанной доставки, `aps-vault[pqc]` — для постквантового конверта) |
| Node | `clients/node/` | встроенные `fetch` и `node:crypto`, Node 20.19+ (`@noble/post-quantum` для постквантового конверта) |
| Go | `clients/go/` | только стандартная библиотека, 1.24+ (crypto/mlkem для постквантового конверта) |
| Java | `clients/java/` | `java.net.http`, Java 11+, один файл (Java 24+ для постквантового конверта) |
| CLI `vault get/put/list` | `ops/vault-cli.sh` | токен из `VAULT_TOKEN`, `~/.vault-token` или `/etc/vault.conf` |
| MCP-сервер | `mcp/` | stdio; даёт агенту `health / list / get / put` в пределах папки токена |
| Расширение браузера | [aps-vault-extension](https://github.com/kzhebenev/aps-vault-extension) | Chrome/Firefox MV3: автозаполнение, TOTP, палитра поиска |

Все клиенты: кеш в памяти, повторы с паузами, отдача устаревшего кеша при недоступности vault
(рестарт vault не роняет сервис; по умолчанию не дольше суток после получения значения, `max_stale`), проверка формы токена (мастер-пароль по ошибке не вставить),
запечатанная доставка (генерация пары ключей и расшифровка у себя). См. [examples/](examples/).

## Чем он не является

- Не каталог пользователей: один владелец с мастер-паролем администрирует всё; именные
  пользователи (0.20) получают роли на папки, но не управляют папками, людьми и настройками.
  Пользователи входят паролем, ключом безопасности (Touch ID, YubiKey) или через SSO.
- Не распределённая база: одиночный узел — один процесс и один файл SQLite (`ops/backup.sh`);
  кластер — одинаковые реплики на одной PostgreSQL, которую вы обслуживаете и бэкапите сами.
- Не KMS: хранит секреты, но не подписывает и не шифрует ваши данные за вас. Свой мастер-ключ
  умеет держать в KMS или HSM и умеет отдавать секреты запечатанными на ключ вашего приложения.

## Статус

В продуктивной эксплуатации у авторов с июня 2026: несколько сотен секретов, несколько десятков
токенов. Ревизия кода 0.4 — [docs/SECURITY-REVIEW-2026-10-02.md](docs/SECURITY-REVIEW-2026-10-02.md). Анализ безопасности
0.36 по коду с SAST, SCA и DAST — [docs/SECURITY-REVIEW-2026-10-05.md](docs/SECURITY-REVIEW-2026-10-05.md): 0.37 закрывает
его 38 находок (1 критическая, 5 высоких), на каждую есть тест, который падает на 0.36. В комплекте
`ops/checks/dast.py` — живые проверки ролей и границ для своего стенда. **Обновление с 0.36 и старше: прочитайте
несовместимые изменения 0.37.0 в [CHANGELOG.md](CHANGELOG.md)** (список владельцев OIDC, клиенты с ключом не
принимают открытый ответ, флаги снимает только владелец). Модель угроз и порядок сообщения об уязвимостях —
[SECURITY.md](SECURITY.md).
