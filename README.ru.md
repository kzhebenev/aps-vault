# APS Vault

Небольшой self-hosted менеджер секретов для одной команды: веб-интерфейс для людей,
machine API со scope-токенами на папку для сервисов и ИИ-агентов, и ничего, что ходит
наружу.

## Зачем ещё один vault

HashiCorp Vault и ему подобные рассчитаны на сотни инженеров и команду, которая их
обслуживает. APS Vault — для обратного случая: несколько человек, десятки сервисов и агентов,
один сервер. Это ~4 000 строк Python и чистого JavaScript, одна SQLite-база, и всё читается
за вечер.

- **Шифрование, которое остаётся шифрованием.** Argon2id выводит мастер-ключ из мастер-пароля;
  у каждой папки свой случайный ключ, завёрнутый мастер-ключом; каждое значение — AES-256-GCM
  со своим nonce. База без мастер-пароля или токена бесполезна.
- **Service-токены на папку.** Токен открывает ровно одну папку и работает даже при
  заблокированном vault — он несёт свою зашифрованную копию ключа папки. По умолчанию только
  чтение; `notes`, `totp` и `write` включаются отдельно на каждый токен.
- **Запечатанная доставка.** Токен привязывается к публичному ключу X25519 приложения, и
  значения уходят из хранилища зашифрованными на него: по пути их не читает никто, а украденный
  токен без ключа бесполезен. Клиенты расшифровывают у себя. См. [docs/SEALED.md](docs/SEALED.md).
- **Machine API прежде всего.** `GET /api/v1/m/secret/<имя>` с Bearer-токеном — всё, что нужно
  сервису. Есть CLI, клиенты на Python, Node, Go и Java, MCP-сервер для агентов; расширение браузера будет опубликовано отдельно.
- **TOTP внутри.** Рядом с паролем хранится 2FA-seed, API отдаёт текущий код.
- **Аудит всего.** Каждая разблокировка, чтение, запись, обращение токена и открытие ссылки —
  с IP и user-agent.
- **Восстановление.** Одноразовый recovery-код перезаворачивает мастер-ключ без
  перешифровки данных. Второй фактор TOTP на мастер-пароль и вход через OIDC — по желанию.
- **Одноразовые ссылки**, история значений, экспорт/импорт JSON, избранное, поиск по Cmd+K.

## Быстрый старт

```bash
git clone https://github.com/<you>/aps-vault.git && cd aps-vault
cp .env.example .env            # заполнить: разрешённые origin'ы, OIDC при необходимости
docker compose up -d --build
open http://localhost:8087      # задать мастер-пароль (≥12 символов), сохранить recovery-код
```

Дальше: папка → секрет → service-токен на эту папку → чтение из сервиса:

```bash
curl -s -H "Authorization: Bearer vlt_…" https://vault.example.com/api/v1/m/secret/db-password
```

Бэкенд ставится за reverse-proxy с TLS: cookie помечены `Secure`, по голому HTTP из браузера
работать не будет. Подробности — в [Развёртывании](docs/DEPLOYMENT.md).

## Чем он не является

- Не многопользовательский: один мастер-пароль на инстанс, ролей в интерфейсе нет. Изоляция —
  между *сервисами* (токены), а не между *людьми*.
- Не распределённый: один процесс, один файл SQLite, один воркер. Бэкап — каталог `data/`
  (`ops/backup.sh`).
- Не KMS: хранит секреты, но не подписывает и не шифрует ваши данные за вас.
